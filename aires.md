# Технические задачи по ИИ-оптимизации (GEO) для PharmNode

В данном документе собраны практические технические задачи, которые необходимо реализовать в кодовой базе проекта (Next.js App Router) для оптимизации платформы под поисковые ответы генеративных сетей (LLM/RAG).

## 1. Инфраструктура и доступность

- **Настройка `robots.txt` (`src/app/robots.ts`)**
  - Разрешить сканирование для поисковых ИИ-роботов: `OAI-SearchBot`, `Claude-SearchBot`, `PerplexityBot`, `ChatGPT-User`.
  - Заблокировать (при необходимости) краулеры, собирающие данные для обучения чужих моделей: `GPTBot`, `ClaudeBot`.
- **Создание `llms.txt` (`public/llms.txt` или API Route)**
  - Разместить в корне файл `llms.txt` (стандарт разметки для LLM) с кратким техническим позиционированием PharmNode (B2B SaaS для расчетов).
  - Добавить ссылки на техническую документацию, тарифы, API и примеры расчетов.
  - При большом объеме документации предусмотреть ссылку на расширенную версию `llms-full.txt`.
- **Серверный рендеринг (SSR / SSG)**
  - Убедиться, что публичные посадочные страницы, блог и документация рендерятся на сервере (используются React Server Components).
  - Исключить клиентский рендеринг (CSR) важного текста (избегать загрузки основного контента через `useEffect`, чтобы краулер не видел пустую страницу).
- **Открытость технической документации**
  - Документация по API, инструкции по матрицам совместимости и расчетам не должны быть скрыты за авторизацией (NextAuth) или Paywall-ом. Краулеры должны иметь к ним свободный доступ.

## 2. Микроразметка (Schema.org / JSON-LD)

Внедрить структурированные данные через JSON-LD (с использованием Next.js Metadata или через `<script type="application/ld+json">`).

- **`Organization`** (На главной странице)
  - Обязательно заполнить свойство `sameAs` ссылками на внешние бизнес-профили (LinkedIn, Crunchbase, G2, Capterra). Это критично для формирования единого графа доверия к бренду.
- **`SoftwareApplication`** (Главная / Продукт)
  - Разметить описание продукта, платформу, категорию (`BusinessApplication`), блок с тарифами (`offers`) и агрегированный рейтинг (`aggregateRating`).
- **`FAQPage`** (Страницы тарифов / Справочный центр)
  - Точечно разметить блоки Q&A (например, детали подписок `hobby` и `professional`, лимиты на ингредиенты).
- **`HowTo`** (База знаний / Руководства)
  - Разметка для технических инструкций (например, пошаговое описание "Как создать рецептуру таблетки").

## 3. Верстка и контентная структура

- **Семантические таблицы (`<table>`)**
  - Сравнения с конкурентами и тарифные сетки должны верстаться с использованием строгих нативных HTML-таблиц. LLM гораздо точнее парсят бинарные матрицы свойств (Да/Нет) из таблиц, чем из визуальных `div/flex` блоков.
- **Принцип Answer-First и независимость пассажей (Passage Independence)**
  - В статьях и базах знаний под каждым заголовком `H2`/`H3` должен сразу идти прямой лаконичный ответ или определение (40–60 слов).
  - Каждый смысловой блок (пассаж) должен быть самодостаточным. Парсер ИИ должен понимать суть абзаца без необходимости анализировать предыдущий текст страницы.
- **Фактологическая плотность вместо "воды"**
  - Исключить размытые маркетинговые эпитеты ("лучшее решение", "самая быстрая работа").
  - Заменить их на твердые факты и метрики платформы (точность расчетов до 4 знаков, наличие алгоритмов Хауснера и Карра, конкретные тайминги ответов API).
