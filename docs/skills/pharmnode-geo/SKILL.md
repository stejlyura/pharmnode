# Generative Engine Optimization (GEO) для PharmNode

Этот скил описывает строгие правила того, как должен быть организован контент и инфраструктура в проекте, чтобы платформу эффективно индексировали ИИ-ассистенты и LLM (ChatGPT, Perplexity, Claude и др.). 
Всегда сверяйтесь с этим файлом при создании новых публичных страниц, компонентов для маркетинга и документации.

## 1. Инфраструктура и доступность (App Router)

- **`robots.txt`**: 
  - ВСЕГДА разрешайте доступ краулерам поисковых ИИ (`OAI-SearchBot`, `Claude-SearchBot`, `PerplexityBot`, `ChatGPT-User`) в `src/app/robots.ts`.
  - При необходимости блокируйте краулеры обучения моделей (`GPTBot`, `ClaudeBot`).
- **`llms.txt`**:
  - В проекте должен поддерживаться `public/llms.txt` или эндпоинт `src/app/llms.txt/route.ts`. 
  - Он должен содержать краткое позиционирование (B2B SaaS для расчетов в фармацевтике), ссылки на тарифы, открытую документацию, API.
- **Рендеринг**:
  - Публичные страницы (лендинги, блог, документация) ОБЯЗАНЫ рендериться на сервере (React Server Components, SSR/SSG).
  - ЗАПРЕЩАЕТСЯ выводить основной текстовый контент через `useEffect` на клиенте, так как краулеры увидят пустую страницу.
- **Документация**:
  - API документация и примеры расчетов должны быть открыты (не защищены NextAuth).

## 2. Микроразметка (JSON-LD)

При добавлении новых страниц интегрируйте JSON-LD через `<script type="application/ld+json">`.

- **`Organization`** (Глобально): Обязательно указывайте поле `sameAs` со ссылками на профили (LinkedIn, Crunchbase, G2, Capterra) для построения графа сущности.
- **`SoftwareApplication`** (Лендинг): Разметка продукта (`BusinessApplication`), тарифов (`offers`) и рейтинга.
- **`FAQPage`**: Для страниц тарифов и справочника. Размечайте блоки вопросов и ответов, чтобы ИИ мог напрямую цитировать лимиты (например, отличия hobby от professional).
- **`HowTo`**: Для пошаговых технических инструкций в базе знаний (например, "Как собрать рецептуру в Node-Based UI").

## 3. Верстка и структура контента

- **Таблицы (`<table>`)**:
  - Сравнения тарифов и конкурентов верстайте строго через нативные HTML-таблицы. 
  - НЕ ИСПОЛЬЗУЙТЕ для многомерных и бинарных данных (Да/Нет) flexbox или grid на базе `div`. LLM извлекают факты из тега `table` намного эффективнее.
- **Answer-First (Ответ в начале)**:
  - В информационных статьях сразу под каждым `H2`/`H3` размещайте прямой лаконичный ответ (40-60 слов). 
  - Контент должен быть контекстно-независимым (Passage Independence): краулер должен понять суть абзаца, не читая предыдущий текст страницы.
- **Фактологическая плотность**:
  - Исключайте из текстов размытые маркетинговые фразы.
  - Оперируйте жесткими фактами: упоминайте точность расчетов (4 знака), специфические алгоритмы (Хауснер, Карр), скорость отработки API.
