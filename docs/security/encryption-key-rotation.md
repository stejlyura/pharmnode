# Процедура ротации ключа шифрования (ENCRYPTION_KEY)

В PharmNode ключ шифрования `ENCRYPTION_KEY` используется для обеспечения конфиденциальности конфиденциальных данных пользователей в базе данных (например, секреты двухфакторной аутентификации `User.twoFactorSecret`).

В случае компрометации ключа или в рамках плановой безопасности необходимо произвести ротацию ключа и перешифровать существующие данные.

---

## Шаг 1. Создание бэкапа базы данных
Перед любыми действиями по ротации ключей обязательно создайте резервную копию базы данных:
```bash
npm run db:backup
```

---

## Шаг 2. Генерация нового ключа шифрования
Сгенерируйте новый 32-байтовый ключ шифрования (в кодировке Base64 или шестнадцатеричном формате):
```bash
# Использование openssl
openssl rand -base64 32
```
Сохраните полученный ключ во временном безопасном хранилище (например, менеджер паролей).

---

## Шаг 3. Запуск скрипта миграции данных
Для перешифрования данных в БД запустите утилиту `rotate-key.ts`. Скрипт принимает текущий ключ как `OLD_ENCRYPTION_KEY` и новый ключ как `NEW_ENCRYPTION_KEY`.

Скрипт выполнит:
1. Чтение всех пользователей с заполненными секретами 2FA.
2. Дешифрование секретов с использованием старого ключа.
3. Шифрование секретов с использованием нового ключа.
4. Сохранение обновленных записей в БД.

### Локальный запуск или запуск в стейджинге:
```bash
OLD_ENCRYPTION_KEY="ваш_текущий_ключ" \
NEW_ENCRYPTION_KEY="ваш_новый_сгенерированный_ключ" \
npx tsx scripts/rotate-key.ts
```

### Запуск на продакшене (через временную сессию консоли):
Если вы деплоите на Vercel, вы можете запустить миграцию через интерактивную консоль Vercel CLI (если подключен доступ к БД) или временно развернуть скрипт на инстансе, имеющем доступ к базе данных продакшена.

---

## Шаг 4. Обновление переменных окружения
После успешного выполнения скрипта обновите значение переменной `ENCRYPTION_KEY` в настройках вашей хостинг-платформы (например, в панели управления Vercel: Project Settings -> Environment Variables).

1. Измените значение `ENCRYPTION_KEY` на ваш **новый** сгенерированный ключ.
2. Перезапустите деплой (Redeploy), чтобы все инстансы приложения начали использовать новый ключ для чтения и записи.

---

## Шаг 5. Верификация
1. Зайдите под тестовым аккаунтом с включенным 2FA.
2. Убедитесь, что одноразовые коды TOTP успешно принимаются при авторизации (что подтверждает успешное дешифрование новым ключом).
3. Проверьте логи на отсутствие ошибок дешифрования.
