# Интеллектуальная база знаний для проектирования лекарственных форм

В данном документе описывается концептуальная архитектура и стратегия развития базы знаний PharmNode для перехода от детерминированной экспертной системы к интеллектуальной платформе поддержки принятия решений (DSS) на основе методов цифрового проектирования препаратов (**Quality by Computational Design, QbCD**).

---

## 1. Концептуальная архитектура базы знаний

Интеллектуальная база знаний строится на принципах 100%-й объяснимости логических выводов (explainability) и аудируемости каждого технологического решения для соответствия стандартам GxP (GMP, GAMP 5) и требованиям FDA.

### Масштабирование структуры данных

| Параметр масштабирования | MVP-версия (Текущая) | Промышленная версия (Целевая) |
| :--- | :--- | :--- |
| **Количество ингредиентов** | 26 базовых компонентов | 5 000 – 10 000+ ингредиентов |
| **Количество уникальных свойств** | 10–15 параметров (плотность, стоимость) | 100–300 параметров (PSD, полиморфизм, растворимость) |
| **Количество связей и правил** | 12 правил совместимости | 100 000+ связей, правил и синергий |

## 2. Интеграция внешних баз данных и источников

Для автоматического наполнения реестра активных фармацевтических субстанций (АФС), нутрицевтиков и вспомогательных веществ планируется интеграция со следующими авторитетными репозиториями через API:

```text
       ┌───────────┐     ┌───────────┐     ┌───────────┐
       │  PubChem  │     │  ChEMBL   │     │ DrugBank  │
       └─────┬─────┘     └─────┬─────┘     └─────┬─────┘
             │                 │                 │
             └─────────────────┼─────────────────┘
                               ▼
            ┌───────────────────────────────────────┐
            │       PharmNode Ingestion Pipeline     │
            └──────────────────┬────────────────────┘
                               ▼
            ┌───────────────────────────────────────┐
            │   PostgreSQL DB (Prisma Schema)       │
            └───────────────────────────────────────┘
```

### Источники для малых молекул и биоактивных соединений
1. **PubChem API**: Извлечение химической структуры, CAS-номеров, физико-химических свойств, токсичности и синонимов (включая USAN и INN).
2. **ChEMBL Database**: Получение биоактивности соединений, механизмов действия и стадий клинических испытаний. Использование InChIKey для сопоставления структуры малых молекул.
3. **DrugBank**: Импорт данных о терапевтических мишенях, метаболических путях, фармакодинамике и фармакокинетике.

### Специализированные базы данных и клинический опыт
* **NIH Dietary Supplement Label Database (DSLD)**: Реестр состава и этикеток БАДов (более 200 000 продуктов) для анализа реальных формул на рынке.
* **USDA Dietary Supplement Ingredient Database (DSID)**: Статистическая оценка фактического содержания активных веществ на основе химического анализа для учета отклонений от этикетки.
* **Clinical Drug Experience Knowledgebase (CDEK)**: База клинического опыта применения ингредиентов человеком (20 000+ ингредиентов) для сопоставления структуры АФС с дозировками и показаниями.

## 3. Регуляторные реестры и физико-механические дескрипторы

Безопасность и технологическая пригодность вспомогательных веществ оценивается через критические материальные атрибуты (CMA).

### Соответствие требованиям FDA
* **FDA Inactive Ingredient Database (IID)**: Ежеквартальный импорт файлов базы данных для верификации статуса вспомогательных веществ (GRAS, NDA, FDA Approved).
* **Расчет MDE (Maximum Daily Exposure)**: Переход от статического показателя максимальной активности к расчету суточного воздействия:
  $$MDE = \text{содержание эксципиента в дозе (мг)} \times \text{максимально рекомендуемое суточное количество единиц препарата (MDD)}$$
* Интеграция с **openFDA** и **DailyMed** (структурированная разметка SPL) для сопоставления путей введения и лекарственных форм.

### Физико-механические дескрипторы порошков
В соответствии с требованиями общей фармакопейной главы USP-NF *Excipient Performance*, в базу данных импортируются реологические дескрипторы коммерческих марок вспомогательных веществ (например, DFE Pharma):

1. **Плотности**: Свободная насыпная плотность ($\rho_{bulk} = \frac{M_0}{V_0}$) и плотность после уплотнения ($\rho_{tapped} = \frac{M_0}{V_f}$).
2. **Индексы сыпучести**:
   * Индекс Карра: $C = 100 \times \left( \frac{\rho_{tapped} - \rho_{bulk}}{\rho_{tapped}} \right)$
   * Отношение Хауснера: $H = \frac{\rho_{tapped}}{\rho_{bulk}}$
3. **Гранулометрический состав**: Распределение частиц по размерам ($x_{10}/x_{50}/x_{90}, \mu\text{m}$).
4. **Влагосодержание**: Критический параметр для влагочувствительных АФС.

## 4. Предиктивное моделирование несовместимостей

Для автоматического предсказания химического взаимодействия АФС с вспомогательными веществами планируется переход от простых табличных связей к структурному анализу.

```text
SMILES / Структура ──► RDKit Parser ──► SMARTS шаблоны (SMARTS-RX) ──► Автоматическое определение класса
```

### Молекулярная детекция на основе SMILES и SMARTS
1. Каждому ингредиенту присваивается структурная формула в нотации **SMILES**.
2. Встроенный парсер (например, на базе RDKit WASM или микросервиса) преобразует SMILES в семантические шаблоны **SMARTS**.
3. Шаблоны сопоставляются с онтологией **SMARTS-RX** (406 паттернов реакционной способности), автоматически выявляя реакционные центры:
   * **Реакция Майяра**: Детекция первичных/вторичных аминов `[NX3,NX4;H2,H1...]` и полуацетального гидроксила восстанавливающих сахаров.
   * **Присоединение по Михаэлю**: Поиск нуклеофильных центров АФС и ненасыщенных связей эксципиентов.
   * **Щелочной гидролиз**: Определение сложных эфиров, амидов и лактамов в щелочной среде стеаратов металлов.

### Экспертные правила и Machine Learning
* **PharmDE / FormulationDE**: Использование стекинговых ансамблей моделей машинного обучения (AUC 0.82), обученных на экспериментальных данных несовместимостей.
* **SHAP force plots**: Визуализация вклада каждой функциональной группы молекулы в общую нестабильность смеси для обеспечения интерпретируемости (explainability).

## 5. Технологический стек автоматизированного извлечения данных (NLP & RAG)

Для поддержки актуальности базы данных используется автоматизированный сбор информации из патентов, научных статей и SmPC.

### Автоматическое извлечение (Information Extraction)
* **ChemDataExtractor**: Использование POS-tagging, CRF (Conditional Random Fields) и химориентированных теггеров для извлечения названий соединений, их физических свойств и единиц измерения из PDF и HTML документов.

### Генеративно-поисковые (RAG) пайплайны
* **Архитектура RAGsemble**: Использование ансамбля больших языковых моделей (Gemini, Claude, GPT) для извлечения параметров рецептур из SmPC документов с показателями F1-меры до 0.98.
* **Text-to-SQL RAG**: Создание интерфейса естественного языка для технологов. В системный промпт модели передаются DDL-схемы таблиц базы знаний и 3-5 демонстрационных строк реальных записей (few-shot), что исключает синтаксические ошибки при генерации SQL-запросов к PostgreSQL.
