# PharmNode — Дорожная карта масштабирования архитектуры

В данном документе описаны архитектурные решения, которые планируется внедрить на этапе масштабирования системы, когда возможностей встроенного бэкенда Next.js перестанет хватать.

## Архитектура при масштабировании

```text
Frontend (Next.js)
    ↓
Backend (NestJS) ← добавляется при росте нагрузки
    ↓
BullMQ Workers ← обработка тяжелых вычислений/очередей в фоне
    ↓
Redis Cache ← кэширование результатов скоринга
    ↓
PostgreSQL
```

### Причины перехода на NestJS
NestJS добавляется только при появлении:
- Сложных фоновых задач и распределенных очередей.
- Необходимости обработки больших объемов данных в реальном времени.
- Потребности в разделении клиентов (отдельные приложения для Web, Mobile, партнерских API).

---

## Система кэширования (Redis)

Для ускорения расчетов матриц совместимости и тяжелых формул планируется использовать **Redis** (например, Upstash Redis для serverless сред).

### Ключи кэша

| Тип | Ключ | TTL |
| --- | --- | --- |
| Ингредиент | `ingredient:{id}` | 24 ч |
| Совместимость | `compatibility:{idA}:{idB}` | — |
| Готовая формула | `formula:sleep`, `formula:immune` | — |
| Граф ингредиента | `ingredient_graph:{id}` | — |

### Предрасчёт данных

Ночные фоновые задачи (cron-джобы) должны предрассчитывать популярные комбинации:
```text
A + B, A + C, A + D → результаты сохраняются в Redis
```

### Materialized Views (PostgreSQL)

Для тяжелых аналитических запросов в админ-панели:
```sql
CREATE MATERIALIZED VIEW top_sleep_ingredients;
REFRESH MATERIALIZED VIEW top_sleep_ingredients;
```

## Планируемая структура монорепозитория

При разделении кодовой базы на фронтенд и микросервисы планируется переход на монорепозиторий (например, с использованием Lerna/Turborepo):

```text
pharmnode/
apps/
├── frontend/     # Next.js приложение холста
├── api/          # NestJS API шлюз
└── admin/         # Админ-панель (отдельное SPA)

packages/
├── shared-types/  # Общие TypeScript интерфейсы
├── scoring-engine/# Расчетный модуль (формулы, пористость)
├── validation/    # Общие правила валидации данных
└── utils/         # Вспомогательные утилиты
```
