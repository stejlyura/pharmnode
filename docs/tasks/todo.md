# Текущие задачи PharmNode

## Инструкции для AI-агента:
> **Контекст**: Проект использует Paddle Billing v2 в качестве платежной системы на стеке Next.js (App Router) + TypeScript + Prisma/PostgreSQL.
> **Архитектура**:
> Frontend — интеграция Paddle SDK через `@paddle/paddle-js`. Инициализация в `src/components/PaddleInit.tsx`.
> Backend — Route Handlers для приема вебхуков от Paddle (`/api/webhooks/paddle`) и валидации подписи с помощью `@paddle/paddle-node-sdk`.
> **Критические правила**:
> 1. Писать только чистый, production-ready TypeScript со строгой типизацией.
> 2. Мы используем **Paddle Billing v2**, а не Stripe, Lemon Squeezy или PayPro Global.
> 3. В обработчиках вебхуков **обязательно** применять валидацию подписей с использованием `PADDLE_WEBHOOK_SECRET`.
> 4. Не делать внутренний UI для управления картами/подписками. Использовать внешний Customer Portal.
> 5. Фокусироваться на безопасной обработке краевых случаев (проверка подписей, отсутствие `userId`, неверные статусы и т.д.).
> 6. **Покрытие тестами**: Все новые фичи должны быть покрыты автоматическими тестами, особенно это касается логина (авторизации) и оплаты (подписок/вебхуков).
> 7. **Запрет на мануальное тестирование AI**: AI не проводит мануальное тестирование. Вместо этого AI должен расписывать задачи по мануальному тестированию и передавать их пользователю для самостоятельной проверки.
