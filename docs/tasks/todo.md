# Текущие задачи PharmNode — Развитие продукта

## Инструкции для AI-агента:
> **Контекст**: Развитие PharmNode от визуализатора рецептур до полноценного B2B-инструмента для создания БАДов (рынки США и ЕС).
> **Критические правила**:
> 1. Все типы — в [`src/types/pharm.ts`](../../src/types/pharm.ts). Не создавать локальных интерфейсов.
> 2. Вся бизнес-логика расчётов — в [`src/lib/calculator.ts`](../../src/lib/calculator.ts). Не дублировать формулы в компонентах.
> 3. Правила совместимости — в [`src/lib/chemicalRules.ts`](../../src/lib/chemicalRules.ts).
> 4. Стейт холста — в [`src/hooks/useNodeEditor.ts`](../../src/hooks/useNodeEditor.ts).
> 5. Никаких `any`. Точность расчётов — до 4 знаков после запятой.
> 6. Перед реализацией новой фичи — прочитать соответствующий SKILL.md.
> 7. Все новые фичи обязательно покрыть автоматическими тестами.
> 8. Интерактивные компоненты → `"use client"` директива.
> 9. CSS переменные тем — в [`src/app/globals.css`](../../src/app/globals.css). Не хардкодить цвета.

## Блок 1: Переход на OAuth-only авторизацию (Google, GitHub)

> **Цель**: Упростить систему регистрации и авторизации, удалив пароли, сброс паролей и собственную 2FA. Пользователи входят в один клик через OAuth. Локальный вход админа по паролю сохраняется для удобства разработки.
> **Бизнес-ценность**: Высокая безопасность, отсутствие необходимости в почтовом сервисе для паролей, чистый код без дублирования функционала безопасности. Премиум-тарифы сохраняются и привязываются к OAuth-аккаунту.

### Задача 1.1: Очистка схемы базы данных
- [x] **Файл**: [`prisma/schema.prisma`](../../prisma/schema.prisma)
- **Что делать**: 
  - Удалить устаревшие поля из модели `User`: `passwordHash`, `twoFactorEnabled`, `twoFactorSecret`, `emailVerificationToken`.
  - Обязательно сохранить поля тарифов и биллинга: `tariff`, `isSubscribed`, `paddleSubId`, `paddleCustomerId`, `variantId`, `renewsAt`, `billingPortalUrl`.
  - Сгенерировать и применить миграцию: `npx prisma migrate dev --name remove_credentials_fields`
- **Тест**: База данных должна успешно мигрировать без потери связи пользователей с рецептами и кастомными ингредиентами.

### Задача 1.2: Обновление конфигурации NextAuth

  - Убедиться, что в колбеке `signIn` новые пользователи создаются с тарифом `hobby` и `isSubscribed: false`.
  - Проверить, что колбек `jwt` по-прежнему запрашивает актуальный тариф (`tariff` и `renewsAt`) из базы данных при каждом запросе, обеспечивая бесшовный доступ к премиум-функциям.
